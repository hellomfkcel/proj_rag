# new-module

创建新的平台能力模块（P-*）或业务模块（B-*）时使用本 Skill。

## 执行步骤

1. 确定模块归属：横切且被依赖 → **平台能力模块（P-*）**；纵向且依赖平台 → **业务模块（B-*）**
2. 填写模块注册表的六个维度（参考 v14.md §0.1）：
   - **职责**：做什么，以及明确不做什么
   - **提供的接口**：对外暴露的全部接口签名
   - **依赖的接口**：依赖哪些其他模块的哪些接口
   - **独占数据**：本模块独占的表或存储
   - **发布事件**：本模块发布哪些领域事件
   - **消费事件**：本模块消费哪些领域事件
3. 在 `src/` 下创建模块目录：
   - 平台模块放在 `src/platform/[模块名小写]/`
   - 业务模块放在 `src/[模块名小写]/`
4. 确定模块依赖方向：B-* → P-* → 外部权限服务（单向，禁止环）
5. 确定每张表有且仅有一个写者模块，写入 `单一写者对照表`（v14.md §0.1.3）
6. 如需审计，区分两类：
   - 普通事件用 `emit_audit_event`（fail-open）
   - 高风险事件（DOC_DOWNLOAD / DOC_DELETE / AUTHZ_WRITE）用 `emit_audit_event_txn`（同事务，fail-closed）
7. 如涉及资源创建/挂载/删除（写路径），按 §13.7 规范同步调用权限服务生命周期端口
8. 如需幂等键，按构造规则生成：`{facade}-{tenant}-{resource_id}[-{kb_id}]-{schema_version}`

## 必须遵守的规范

- 模块注册表六维度必须完整填写，缺一不可
- B-* 只能依赖 P-*，不得反向依赖
- 业务模块之间只允许「内部接口调用」或「事件」，禁止直读直写对方独占表
- 平台模块之间互不依赖对方业务态
- 每张表有且仅有一个模块可写（单写原则）
- 所有 `audit_log` 写入必须记录 `authz_decision_ref`（跨系统审计主键）
- 写路径调用权限服务：先调权限服务，成功后再提交本地事务；失败/超时即回滚
- 幂等键必须确定性可重算，`result: "noop"` 视为成功，同 key 不同载荷返回 409 必须告警
- 框架使用原则：编排、状态机、数据模型自持；算法性组件委托 Haystack 2.x 经 `@component` 防腐层引入

## 禁止事项

- 禁止业务模块 import 可观测后端 SDK —— 一律经 P-OBS 门面
- 禁止业务模块自行拼装 Collector/后端地址
- 禁止业务模块自行拼装权限服务地址、自行构造 Envelope、自行解释 reasons
- 禁止任何模块越过 P-AUTHC 直接调用权限服务 HTTP 端点
- 禁止依赖环
- 禁止在 Haystack Component 内部旁路 P-MODEL 门面调用模型
- 禁止在 Haystack Component 内部写权限判断逻辑
- 禁止时间戳/随机数/UUID 作为幂等键
- 同一事务内对权限服务的调用禁止重试（超时 ≤2s）

## 目录结构模板

### 平台模块

```
src/platform/[模块名]/
├── __init__.py              # 公开接口导出
├── [模块名]_service.py      # 核心业务逻辑
├── [模块名]_models.py       # 数据模型（如有独占表）
└── [模块名]_exceptions.py   # 模块特有异常
```

### 业务模块

```
src/[模块名]/
├── __init__.py              # 公开接口导出
├── [模块名]_service.py      # 核心业务逻辑
├── [模块名]_models.py       # 数据模型（独占表）
├── [模块名]_events.py       # 发布/消费事件定义
├── [模块名]_exceptions.py   # 模块特有异常
└── components/              # Haystack @component（如适用）
    └── [组件名].py
```
