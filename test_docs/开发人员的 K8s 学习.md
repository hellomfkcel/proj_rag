# 🗺️ 学习路线图总结

```
第1阶段 [入门]     Docker → K8s 架构 → kubectl 基础
    ↓
第2阶段 [初级]     Pod → Deployment → Service → Ingress
    ↓
第3阶段 [中级]     ConfigMap/Secret → PV/PVC → Namespace
    ↓
第4阶段 [中高级]   RBAC → NetworkPolicy → 调度策略 → 健康检查
    ↓
第5阶段 [高级]     Helm → CRD/Operator → 监控 → CI/CD → 服务网格
    ↓
第6阶段 [精通]     多集群管理 → 性能调优 → 安全加固 → 灾难恢复
```

> 💡 **学习建议**：理论与实践结合，建议使用 **Minikube** 或 **kind** 搭建本地集群进行练习，逐步过渡到云环境（EKS/AKS/GKE），最终考取 **CKA/CKAD** 认证来检验自己的水平。



# 🎯 开发人员的 K8s 学习深度指南

## 一句话结论

> 开发人员一般学到 **第3~4阶段（中级）** 就足够了，第5~6阶段留给 **DevOps / SRE / 平台工程师**。

## ✅ 开发人员【必须掌握】的内容

### 第1阶段 — 基础概念
| 内容           | 重要程度  | 说明            |
| ------------ | :---: | ------------- |
| K8s 架构原理     |  ⭐⭐⭐  | 知道大致架构，面试够用即可 |
| kubectl 基本操作 | ⭐⭐⭐⭐⭐ | 日常高频使用        |
| YAML 编写      | ⭐⭐⭐⭐⭐ | 每天都要写         |

### 第2阶段 — 核心资源
| 内容         | 重要程度  | 说明          |
| ---------- | :---: | ----------- |
| Pod 概念与调试  | ⭐⭐⭐⭐⭐ | 看日志、进容器排查问题 |
| Deployment | ⭐⭐⭐⭐⭐ | 最常用的工作负载    |
| Service    | ⭐⭐⭐⭐⭐ | 理解服务间怎么互相调用 |
| Ingress    | ⭐⭐⭐⭐  | 理解外部流量怎么进来  |

### 第3阶段 — 配置与存储
| 内容        | 重要程度  | 说明              |
| --------- | :---: | --------------- |
| ConfigMap | ⭐⭐⭐⭐⭐ | 配置管理日常使用        |
| Secret    | ⭐⭐⭐⭐⭐ | 密码/密钥管理         |
| PVC 使用    |  ⭐⭐⭐  | 知道怎么挂载，PV 由运维创建 |
| Namespace | ⭐⭐⭐⭐  | 环境隔离            |

### 第4阶段 — 部分掌握即可
| 内容                 | 重要程度  | 说明                      |
| ------------------ | :---: | ----------------------- |
| 健康检查（探针）           | ⭐⭐⭐⭐⭐ | **必须掌握！** 直接影响应用可用性     |
| 资源 requests/limits | ⭐⭐⭐⭐⭐ | **必须掌握！** 不设置会被 OOMKill |
| HPA                |  ⭐⭐⭐  | 理解原理，配置可由运维协助           |
| RBAC               |  ⭐⭐   | 了解即可，一般运维配              |

## 🔍 开发人员的日常 K8s 场景

```
日常工作中你 80% 的时间只需要这些：

┌──────────────────────────────────────────────┐
│  1. 写 Dockerfile，构建镜像                    │
│  2. 写 Deployment + Service YAML             │
│  3. 配置 ConfigMap / Secret                   │
│  4. 配置健康检查探针                            │
│  5. kubectl logs / exec / describe 排查问题   │
│  6. 看 Pod 事件和状态，定位启动失败原因          │
│  7. 理解 CI/CD 流水线中 K8s 部署的环节         │
└──────────────────────────────────────────────┘
```

### 💻 一个开发者的典型工作流

```bash
# 1️⃣ 本地开发完成后，构建镜像
docker build -t myapp:v1.2.3 .
docker push registry.company.com/myapp:v1.2.3

# 2️⃣ 更新部署文件中的镜像版本
# deployment.yaml → image: registry.company.com/myapp:v1.2.3

# 3️⃣ 部署到开发/测试环境
kubectl apply -f k8s/ -n dev

# 4️⃣ 检查部署状态
kubectl get pods -n dev
kubectl rollout status deployment/myapp -n dev

# 5️⃣ 出问题了？排查！
kubectl describe pod myapp-xxx -n dev    # 看事件
kubectl logs myapp-xxx -n dev            # 看日志
kubectl exec -it myapp-xxx -- /bin/sh    # 进容器

# 6️⃣ 有问题？回滚！
kubectl rollout undo deployment/myapp -n dev
```

## ❌ 开发人员【不需要深入】的内容

| 内容                       | 负责人    | 开发者了解程度   |
| ------------------------ | ------ | --------- |
| 集群搭建（kubeadm/二进制）        | 运维/SRE | ❌ 不需要     |
| etcd 维护与备份               | 运维/SRE | ❌ 不需要     |
| CNI 网络插件（Calico/Flannel） | 平台工程   | ❌ 不需要     |
| StorageClass / PV 创建     | 运维     | 🔸 了解概念   |
| 节点调度策略（亲和性/污点）           | 运维/SRE | 🔸 了解概念   |
| NetworkPolicy 细节         | 安全/SRE | 🔸 了解概念   |
| Istio 服务网格               | 平台工程   | 🔸 了解概念   |
| CRD / Operator 开发        | 平台工程   | 🔸 除非业务需要 |
| 集群升级与安全加固                | 运维/SRE | ❌ 不需要     |
| 多集群管理                    | 平台工程   | ❌ 不需要     |

## 💡 总结

| 问题            | 答案                             |
| ------------- | ------------------------------ |
| **学到哪里够用？**   | 第3阶段 + 第4阶段的探针和资源限制            |
| **面试要求？**     | 一般考到 Service 类型区别、滚动更新、探针、资源管理 |
| **要不要考 CKA？** | 后端开发建议考 **CKAD**（更偏应用），CKA 偏运维 |
| **什么时候需要深入？** | 转 DevOps/SRE，或负责团队基础设施时        |

> 📌 **黄金法则**：开发人员把精力放在 **「怎么在 K8s 上跑好我的应用」**，而不是 **「怎么搭建和维护 K8s 集群」**。把专业的事交给专业的人。
